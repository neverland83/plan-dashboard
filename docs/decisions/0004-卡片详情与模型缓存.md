# ADR-0004: 卡片详情弹框 - Model Info + Plan 档级缓存

- 日期：2026-08-29
- 状态：已接受
- 任务 brief：`docs/task-briefs/2026-08-29-model-info-and-plan-cache.md`

## 背景

卡片只显示各窗口用量百分比，用户不知道自己买的是哪档 Plan（智谱 Lite/Pro/Max、火山 Coding/Agent Plan 档级等），也看不到该 Plan 覆盖哪些模型。每次打开详情都请求第三方 API 又太浪费（限流 + 延迟）。

## 决策

1. **缓存存储**：`data/model_cache.json` 单文件，顶层 `{provider_id: {...}}`（D1/D7'），与 config.json 同风格的纯文件；原子写（临时文件 + os.replace）；运行时产物不入库
2. **失效策略**：首查 → 之后读缓存 → 手动按钮刷新（D2）。对应路由语义：`GET /info` 无缓存才查，`POST /refresh-info` 永远重查
3. **弹框 UI**：原生 HTML `<dialog>` 覆盖层，深色科技风（D3）；模型列表可搜索 + 滚动
4. **模型数据来源**：各家 OpenAI 兼容 `/v1/models` 或控制面 API（D4）：
   智谱 `{host}/api/paas/v4/models` · MiniMax `{host}/v1/models` · DeepSeek `/models` ·
   Kimi `{host}/v1/models` · StepFun `/v1/models` · 百炼 dashscope compatible-mode（有 key 才查）·
   火山管控面 `ListFoundationModels`（V4 签名，与套餐查询共用认证）
5. **plan_name 三层回退**（D5'）：adapter 自报 → config.json 条目 `plan_name` 手填 → 前端显示「按量调用 / 未知档级」
6. **刷新按钮位置**：卡片右下角「☰ 详情」图标进入，弹框内「刷新 ↻」按钮（D6'）

## 后果

- 打开弹框常态零请求（读本地缓存），第三方 API 不被打爆
- 缓存带 `fetched_at` + `plan_name_source`，前端可标注数据新旧与档级来源
- 手动型（manual）无查询能力，详情弹框显示空列表 + config 手填档级（`supports_models = False` 标记能力，空列表不视为错误）
- DeepSeek/Kimi/StepFun 等按量/无 API 厂商 plan_name 走手填或「按量调用」兜底
