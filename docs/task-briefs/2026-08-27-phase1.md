## 功能需求（分点）

### 后端
1. FastAPI 服务，仅监听 127.0.0.1（默认端口建议 8712 或可配）
2. `GET /api/plans`：返回所有启用的 provider 条目 + 各自用量数据（含错误状态）
3. `POST /api/refresh`：手动触发刷新全部
4. `GET/POST /api/config`：读取/保存配置（config.json）
5. `GET /api/providers`：返回支持的厂商类型清单（id/名称/是否需要额外配置）
6. 定时刷新：后台线程定时拉取，避免阻塞请求
7. 每个 provider 条目独立容错：单个厂商失败不影响其他卡片，失败状态带 error 信息返回

### 适配器（严格按 docs/research/providers/*.md 的接口档案实现）
1. **zhipu**：`GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`，Header `Authorization: <裸key>`（无 Bearer）；解析 `data.limits[]`：TIME_LIMIT（5小时窗口）/ TOKENS_LIMIT（周窗口），percentage 为已用%，剩余 = 100 - percentage；nextResetTime 用于倒计时。支持 `extra.host` 覆盖（Z.ai 用 `https://api.z.ai`）
2. **minimax**：接口细节**需从 CC Switch 源码确认**（见 community-implementations.md §1，克隆仓库看 `src-tauri/src/services/balance.rs` MiniMax 分支）；新接口返回剩余百分比；过滤非编程模型；兼容无周限额
3. **deepseek**：`GET https://api.deepseek.com/user/balance`，Bearer 认证；解析 balance_infos（total/granted/topped_up + is_available）；无窗口，按"余额型"展示
4. **kimi**：`GET https://api.moonshot.cn/v1/users/me/balance`，Bearer 认证；解析 data.available_balance/voucher_balance/cash_balance
5. **ark（火山方舟）**：官方 OpenAPI `POST https://ark.cn-beijing.volcengineapi.com/?Action=GetUsageDetails&Version=2024-01-01`，需要 AccessKey/SecretKey V4 签名（用 volcengine 官方 Python SDK 或自行实现签名）；注意 2026-08-12 后新 Key 用 ApiKeyID 查询；套餐上限需用户在配置里填（extra.plan_quota），剩余% = (配额-已用)/配额
6. **manual**：从配置 extra.windows 直接读百分比返回

### 前端（index.html）
1. 卡片式布局：每 provider 一张卡，显示厂商名/套餐名/各窗口剩余百分比
2. **多窗口显示**（参照 CC Switch）：如智谱显示 "5小时: 99% / 7天: 80%" + 重置剩余时间（如 4h37m / 1d16h）
3. 剩余百分比用环形进度（SVG stroke-dasharray 实现，不引大库）或进度条；颜色分级：>50% 绿 / 20-50% 黄 / <20% 红
4. 余额型厂商（DeepSeek/Kimi）显示余额金额 + 可用状态（is_available）
5. 手动型卡片带"手动"标记
6. 手动刷新按钮 + 显示上次更新时间 + 自动定时刷新（轮询 /api/plans）
7. 配置面板：增删改 provider 条目（类型选择、API Key 输入、启用开关、手动型可填窗口百分比）
8. 深色科技风，中文界面
9. API Key 绝不出现在前端数据里（/api/plans 不返回 key）
